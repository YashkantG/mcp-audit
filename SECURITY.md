# Security Policy

## Reporting a vulnerability in mcp-triage itself

Please report security issues in the scanner privately, via
[GitHub's private vulnerability reporting](https://github.com/YashkantG/mcp-triage/security/advisories/new)
rather than a public issue.

Expect an initial response within 7 days. If a fix is warranted, it ships in a
patch release and the advisory is published once users have had a reasonable
window to upgrade.

### What counts as a vulnerability here

`mcp-triage` is a local static analyser with a deliberately small attack
surface — it reads files and writes a report. Things that would qualify:

- **Code execution while scanning.** The scanner must never execute, import,
  or evaluate the code it is analysing. Any input file that causes execution
  is a serious bug.
- **Path traversal / writes outside the working directory.** The scanner
  should only ever read from the scan target.
- **Denial of service on hostile input** — e.g. a crafted file that triggers
  catastrophic regex backtracking and hangs a CI job indefinitely.
- **Leakage of scanned content** anywhere other than the output stream the
  user asked for.

### What does not count

- **A missed detection (false negative).** The tool is explicitly a
  pattern-based first pass, not a complete analyser — it makes no soundness
  guarantee. Missed detections are ordinary bugs; please
  [open an issue](https://github.com/YashkantG/mcp-triage/issues/new/choose)
  so a rule can be added.
- **A false positive.** Also an ordinary bug, also welcome as an issue.

## Reporting a vulnerability you found *with* mcp-triage

If this tool helped you find a real issue in **someone else's** MCP server,
please disclose it to that project privately first. Do not open a public
issue here naming a third-party project as vulnerable.

This matters more than usual in the MCP ecosystem: most servers are small,
recently written, and maintained by one person. A public "project X is
insecure" post — especially one generated by an automated scan that may
contain false positives — does real reputational harm and discourages exactly
the kind of open publishing the ecosystem needs.

## Our own supply chain

- Releases are published through
  [PyPI Trusted Publishing](https://docs.pypi.org/trusted-publishers/) (OIDC),
  so there are no long-lived tokens to steal, and each release traces back to
  the GitHub Actions run that built it.
- Runtime dependencies are deliberately minimal: `typer`, `rich`, and `tomli`
  (Python < 3.11 only). Additions are reviewed sceptically — see
  [CONTRIBUTING.md](CONTRIBUTING.md).
- The scanner makes **no network calls** at runtime.
